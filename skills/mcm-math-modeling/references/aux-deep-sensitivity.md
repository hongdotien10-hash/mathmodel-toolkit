# 深度敏感性分析

## 数学建模规范参考

读取 `references/math_modeling_norms.md`（相对 skill 根目录，下同） 中的「灵敏度分析规范」小节和 `references/innovations.md` 中的「创新的五个维度-维度4」小节。

## 前置条件

必须先有 `reports/RESULTS_REPORT.md` 或等价的求解结果记录（含关键参数、目标函数值和约束检查结果）。若不存在，提示用户先运行 `3coding-visual`。

## 必须产出

在 `reports/` 目录中创建：

- `reports/SENSITIVITY_REPORT.md`：完整灵敏度分析报告，含方法选择、分析结果、关键发现和论文可直接引用的叙事文本。
- 在 `figures/` 目录中生成灵敏度分析图表（≥3 张）。

## 计算深度硬性标准

**敏感性分析的竞争力来自计算深度。±10% 的单参数扰动只是及格线，不是亮点。以下标准对标 Modex 的深度计算理念：**

| 分析类型 | 硬性最低标准 | 为什么 |
| --- | --- | --- |
| **单参数扰动** | 覆盖参数合理范围的 ≥ 60%（不是 ±10%），步长 ≤ 范围的 5% | ±10% 可能完全错过参数的非线性影响区 |
| **Sobol 全局敏感性** | Saltelli 采样，N ≥ 1024（即模型评估次数 = N×(D+2)，D 为参数个数） | N < 512 时 Sobol 指数置信区间过宽，结论不可靠 |
| **Morris 筛选** | trajectories ≥ 100，levels ≥ 8 | 少于 50 条轨迹时 μ* 排序不稳定 |
| **相变边界探测** | 步长 ≤ 参数范围的 2%，连续监测输出的一阶/二阶差分 | 步长太大会跳过窄相变窗口 |
| **启发式算法稳定性** | ≥ 20 次独立运行，报告均值±标准差±变异系数 | 单次运行方差可达 15%+，不足以说明稳定性 |
| **约束敏感性** | 每个紧约束做 ±20% 范围内的 10 等分扫描 | 影子价格只在约束紧时有效，需要验证线性区域范围 |

**在 `reports/SENSITIVITY_REPORT.md` 开头「方法选择」小节中，必须列出实际计算量（如 Sobol N=2048, 模型评估 24576 次），并注明「达标」或「未达标+原因」。**

## 求解器真实性要求（适用于敏感性分析）

**敏感性分析的每次参数评估 = 一次完整的模型求解，不是参数乘系数。**

| 违规做法（❌） | 正确做法（✅） |
| --- | --- |
| 利润 = 基准利润 × yield_factor × price_factor | 用新的参数值重新构建优化模型 → 调用求解器 → 获取新的最优利润 |
| 1000 个情景 = 1000 次 `for` 循环乘系数 | 1000 个情景 = 1000 次独立调用求解器 |
| Sobol 评估 = 公式代值，0.001 秒/次 | Sobol 评估 = 完整求解，可能 10-300 秒/次 |
| 代码中没有任何求解器调用 | 代码中必须出现 `solver.solve()` / `.optimize()` / `.minimize()` 等调用 |

**验证方法**：在 `SENSITIVITY_REPORT.md` 中截取求解器输出日志的前 20 行和后 10 行，证明每次评估确实调用了求解器。

**预计耗时**：Sobol 全局敏感性分析可能需要 30-120 分钟（取决于单次模型评估耗时）。这不是浪费时间——Modex 类工具一跑几小时，计算深度正是其核心竞争力。

## 工作流程

### Step 0: 分析层级判断

根据建模报告判断灵敏度分析的适合层级，不要盲目做全局敏感性分析：

| 判断条件 | 推荐层级 | 硬性计算量 |
| --- | --- | --- |
| 参数 ≤ 5 个，模型运行快（< 1 秒/次）| 必须做全局敏感性分析（Sobol，N ≥ 1024） | 模型评估 ≥ 1024×(D+2) 次 |
| 参数 5-15 个，模型运行适中（< 10 秒/次）| Morris 筛选（trajectories ≥ 100）+ 关键参数 Sobol | Morris ≥ 100 轨迹；Sobol 对 Top 3 参数 N ≥ 1024 |
| 参数 > 15 个，或模型运行慢（> 10 秒/次）| Morris 筛选（trajectories ≥ 100）+ 单参数深入 + 交互效应定性分析 | Morris ≥ 100 轨迹；单参数扫描 ≥ 20 个采样点 |
| 封闭形式解 / 线性模型 | 直接用解析灵敏度（导数/弹性系数） | 无需计算量下限，但需列出弹性系数矩阵 |
| 启发式算法（GA/SA/PSO）| ≥ 20 次独立运行稳定性 + 关键参数扰动（≥15 个采样点） | 20 次独立运行 × ≥ 3 个关键参数 × 15 采样点 |

在 `SENSITIVITY_REPORT.md` 开头写明选择理由和实际计算量。

### Step 1: 参数清单和范围确定

从建模报告和结果记录中提取所有关键参数：

```markdown
## 参数清单

| 参数 | 符号 | 基准值 | 取值范围 | 来源 | 敏感性预期 |
| --- | --- | --- | --- | --- | --- |
| ... | α | 0.5 | [0.3, 0.7] | 文献/估计/假设 | 高/中/低 |
```

敏感性预期（高/中/低）是基于建模经验的主观预判，用于检验后续分析结果是否合理。

### Step 2: 单参数敏感性分析（基础层，必做）

对每个关键参数做充分范围的扰动。**硬性要求：覆盖参数合理范围的 ≥ 60%，不是机械地 ±10%。**

```markdown
## 单参数扰动分析

### 参数：α（范围 [0, 1]，基准值 0.5）

| α 值 | 变化幅度 | 目标函数值 | 相对变化 | 关键约束状态 |
| --- | --- | --- | --- | --- |
| 0.1 | -80% | ... | ... | ... |
| 0.2 | -60% | ... | ... | ... |
| 0.3 | -40% | ... | ... | ... |
| 0.4 | -20% | ... | ... | ... |
| 0.5 | 0%（基准）| ... | 0% | ... |
| 0.6 | +20% | ... | ... | ... |
| 0.7 | +40% | ... | ... | ... |
| 0.8 | +60% | ... | ... | ... |
| 0.9 | +80% | ... | ... | ... |
```

扰动范围要根据参数的实际物理/业务含义确定，不要机械地 ±10%/±20%：
- 权重组参数：0 ~ 1 全覆盖（10+ 个采样点）
- 物理参数：覆盖物理约束的合理范围（≥ 60%）
- 由数据估计的参数：估计值 ± 2 倍标准误（≥ 10 个采样点）

### Step 3: 全局敏感性分析（进阶层，条件必做）

如果 Step 0 判断适合，执行全局敏感性分析：

#### 3a. Morris 方法（参数筛选）

用途：从多个参数中筛选出真正有影响力的那几个。

```python
from SALib.sample import morris
from SALib.analyze import morris as morris_analyze
```

输出：
- μ*（参数主效应估计，越大越重要）
- σ（参数交互效应/非线性效应，越大说明该参数影响越非线性或越依赖其他参数）
- μ*/σ 散点图（横轴主效应，纵轴交互效应）

#### 3b. Sobol 方法（方差分解）

用途：精确量化每个参数的贡献比例。

```python
from SALib.sample import saltelli
from SALib.analyze import sobol
```

输出：
- 一阶敏感指数 S1（该参数独立解释的方差比例）
- 全效应指数 ST（该参数及其所有交互项共同解释的方差比例）
- ST - S1（纯交互效应贡献）
- Sobol 指数条形图 + 热力图

#### 3c. 交互效应可视化

对 Top 3-4 个关键参数，画交互效应图：
- 二维等高线/热力图：X 轴参数 A，Y 轴参数 B，颜色为输出值
- 若存在明显的非加性交互（ST - S1 > 0.1），生成参数交互叙事

### Step 4: 相变边界探测（高阶）

判断结论是否会在参数空间的某处发生「质变」：

```markdown
## 相变边界分析

**探测方法**：
- 对关键参数做细粒度扫描（步长 ≤ 5%）
- 监测输出是否出现不连续跳变、斜率突变或符号翻转
- 记录相变边界位置和相变前后的系统行为差异

**关键发现**：
- 相变边界 α ≈ 0.35：当 α < 0.35 时，最优策略为 A；α > 0.35 时，最优策略切换为 B
- 相变机制：...
```

相变分析是获奖论文的高级加分点，但只在确实存在相变时才做，不要强行制造。

### Step 5: 约束敏感性（优化类问题专项）

对优化类问题，分析约束右端项的敏感性（影子价格/对偶变量）：

```markdown
## 约束敏感性分析

| 约束 | 基准值 | 松弛量 | 影子价格 | 放宽 10% 目标改善 | 收紧 10% 目标恶化 |
| --- | --- | --- | --- | --- | --- |
| 预算约束 | 1000 | 0（紧）| 2.3 | +23 | -23 |
| 时间约束 | 480 | 50（松）| 0 | 0 | 0 |
```

- 紧约束（松弛量 = 0）+ 影子价格高 → 瓶颈，是资源增加的最优先方向
- 松约束（松弛量 > 0）+ 影子价格 = 0 → 当前不是限制因素

### Step 6: 稳定性/鲁棒性分析

对使用随机算法的模型：

```markdown
## 求解稳定性分析

| 统计量 | 目标函数值 | 运行时间 (s) |
| --- | --- | --- |
| 均值 | ... | ... |
| 标准差 | ... | ... |
| 变异系数 (CV) | ... | ... |
| 最优值 | ... | ... |
| 最差值 | ... | ... |
| 运行次数 | 20 | 20 |
```

CV < 2% → 稳定；CV 2-10% → 可接受；CV > 10% → 不稳定，需要更多运行或改进算法。

### Step 7: 分析叙事（论文可直接使用）

将上述所有分析结果，编织成论文中可直接使用的叙事文本：

```markdown
## 灵敏度分析叙事文本

### 主要发现（用于论文灵敏度分析章节）

1. **模型对参数 X 最敏感**：X 变化 10% 导致目标值变化 Y%，这是因为...
2. **参数 Z 的影响存在阈值效应**：当 Z < 阈值时，系统行为为 A；Z > 阈值时，切换为 B。这个阈值是...
3. **参数 W 的交互效应显著**：W 和 V 存在明显的非加性交互（Sobol 交互指数 = ...），说明...
4. **模型整体鲁棒性良好/一般/较差**：ST > 0.1 的参数占 X%，其中 Y 个是模型假设的参数（非数据估计），需要额外关注...

### 论文写作建议

- 在灵敏度分析章节中先给出主要发现，再展示图表
- 不要只说「参数 α 有影响」，要说「α 每增加 X%，目标值变化 Y%，影响呈线性/非线性」
- 如果有相变发现，作为亮点在摘要中提及
- 如果某个假设参数非常敏感，在模型评价中说明这是模型的局限
```

### Step 8: 图表生成

至少生成以下图表（存为 `figures/` 中的 PDF）：

1. **Tornado 图**（单参数敏感性汇总）：按影响从大到小排列
2. **一维扰动曲线**（关键参数 2-3 个）：X 轴参数值，Y 轴输出
3. **交互效应热力图**（如有显著交互）：二维参数空间 + 输出颜色

图表标准：参考 `mrite-figure` 和 `nature-figure` 的论文级图表规范。

## 质量要求

- 扰动范围不能只有 ±10%，必须覆盖参数合理范围的 ≥ 60%。
- **硬性计算量达标**：在报告开头列出各项计算量的实际值和达标状态。未达标的需说明原因。
- 全局敏感性分析不是必选项，在模型运行快、参数少时才做；不要为了炫技而做不必要的复杂分析。
- 所有数值必须可复现（保存随机种子、参数设置和运行记录）。
- Sobol 分析必须报告置信区间（S1_conf, ST_conf），不能只报点估计。
- 叙事文本必须给出「所以呢？」——不仅说参数有影响，还要说影响有多大、意味着什么、怎么应对。
- 如果分析发现模型对某个假设参数极度敏感（如 5% 的扰动导致 50% 的结果变化），必须标记为模型的重大局限。
- 图表必须与叙事文本一致，图表中出现的数值必须在叙事文本中提及。
- **预计耗时明确告知**：执行前告知用户预计计算时间，执行中定期报告进度。
