# 交互式决策门

## 定位

本 skill 是数学建模工作流中的 **「人机决策接口」**。在需要判断力、审美、经验或风险权衡的关键节点，AI 不应该自行决定——它应该：

1. 识别决策点
2. 生成候选选项
3. 分析每个选项的优劣
4. 标注推荐强度
5. **弹出选项让你来选**
6. 记录你的选择，注入后续流程

## 触发时机

以下节点应主动触发本 skill：

| 决策节点 | 触发时机 | 决策内容 |
| --- | --- | --- |
| **方向确认** | `2analysis-modeling` 完成后 | 假设解释选择、总体建模路线 |
| **模型选型** | `model-comparison` 完成后 | 各子问题最终方法选择 |
| **创新取舍** | 模型选型确认后 | 追求稳妥还是冒险创新 |
| **图表策略** | `3coding-visual` 完成后 | 哪些图表进论文、哪些放附录 |
| **叙事重心** | `5writing` 开始前 | 论文强调方向（方法创新 vs 结果扎实 vs 分析深度） |
| **摘要方向** | `abstract-polish` 中 | 多个摘要版本的选择或混合策略 |

也可以在用户说「帮我选」「你觉得哪个好」「给个建议」时主动调用。

## 工作流程

### Step 1: 读取当前状态

确认当前阶段和可用信息：

```
当前阶段: [从上下文判断]
已有产物: [列举可读取的报告文件]
待决策事项: [扫描上下文中的未决问题]
```

### Step 2: 梳理决策清单

把当前阶段的所有待决策事项整理为结构化决策列表。决策粒度：

- **太细** → 合并（「选 sklearn 还是自写 K-means」合并为「K-means 实现方式」）
- **太粗** → 拆开（「论文方向」拆为「结构组织」「亮点强调」「图表策略」）
- **可自动决定的** → 不要拿出来问（如缺失值用均值填充 vs 中位数填充，除非数据分布异常）

### Step 3: 格式化决策

对每个决策，生成如下格式的问题和选项：

```markdown
## 决策：[简短标题]

**背景**：[2-3 句说明当前上下文和为什么需要这个决策]

**为什么需要你来选**：[说明 AI 无法自动判断的原因——各有优劣、依赖偏好、涉及风险权衡、需要领域经验]

### 选项

| 选项 | 分析 | 推荐度 |
| --- | --- | --- |
| A: [标签] | [2-3 句分析：为什么选这个、有什么好处、有什么风险] | ⭐⭐⭐ / ⭐⭐ / ⭐ |
| B: [标签] | [同上] | ... |
| C: [标签] | [同上] | ... |
```

**推荐度含义**：
- ⭐⭐⭐ 强烈推荐：在当前条件下是最优或最稳妥的选择，除非你有特殊理由
- ⭐⭐ 推荐：合理选择，有特定优势但也有取舍
- ⭐ 可考虑：在某些偏好下有价值，但有明显代价或风险

**选项设计规则**：
- 每个决策 2-4 个选项
- 至少有一个 ⭐⭐⭐（表明 AI 的明确态度）
- 不能全是 ⭐⭐⭐（否则不需要决策）
- 选项之间必须有实质差异，不能是同一方案的不同措辞

### Step 4: 弹出选择

使用 `AskUserQuestion` 工具，一次呈现 1-4 个决策问题：

每个问题的选项在 label 中包含推荐度标记：

```
header: "模型选型"
question: "问题一的核心模型选择哪个？"
options: [
  {label: "AHP+TOPSIS（⭐⭐⭐）", description: "成熟稳定，评委熟悉，可解释性强。风险：创新性不足，可能淹没在大量同类论文中"},
  {label: "AHP+熵权组合+TOPSIS（⭐⭐）", description: "主客观结合，有方法组合创新。代价：需论证组合权重的合理性，增加建模篇幅"},
  {label: "云模型+TOPSIS（⭐）", description: "创新性强，处理模糊性。风险：评委可能不熟悉，需要更多篇幅解释方法"}
]
```

**如果用户选了「Other」**，将自定义输入解析为新的决策方向，在下一个问题中确认。

### Step 5: 记录决策

在 `reports/DECISIONS.md` 中追加记录：

```markdown
## [日期时间] [决策标题]

**阶段**：[当前阶段]
**决策点**：[决策标题]
**用户选择**：[选中的选项]
**理由**：[用户自定义输入的理由，如有]
**影响范围**：[此决策影响哪些后续步骤]
```

### Step 6: 将决策注入后续流程

根据用户选择，更新相关产物：

- 模型选择 → 更新 `MODEL_SELECTION_REPORT.md` 中的最终选型
- 假设解释 → 更新 `ANALYSIS_MODELING_REPORT.md` 中的假设选择
- 图表策略 → 在 `RESULTS_REPORT.md` 中标注进论文/进附录的图表
- 叙事重心 → 在论文撰写时按选定方向分配篇幅和强调

## 各阶段决策模板

### 模板 1：方向确认决策（2analysis-modeling 完成后）

```markdown
## 决策 1：模糊假设的解释选择

**背景**：题面中 [具体表述] 存在歧义，可以解释为 A 或 B。

**为什么需要你来选**：两种解释都合理，但会导致完全不同的建模方向。AI 无法判断出题人的真实意图。

### 选项

| 选项 | 分析 | 推荐度 |
| --- | --- | --- |
| A: 解释为 [保守解释] | 最直接的解读，多数队伍会采用。风险：[什么情况下会翻车] | ⭐⭐⭐ |
| B: 解释为 [扩展解释] | 考虑更全面，但模型复杂度增加 X 倍。优势：[什么情况下出彩] | ⭐⭐ |
```

### 模板 2：模型选型决策（model-comparison 完成后）

```markdown
## 决策 2：[子问题X] 最终方法选择

**背景**：经过多模型对比（详见 MODEL_SELECTION_REPORT.md），问题 X 有 3 个候选方法。

**为什么需要你来选**：不同方法在精度、复杂度、创新性之间权衡不同，取决于你想要激进还是稳妥的策略。

### 选项

| 选项 | 分析 | 推荐度 |
| --- | --- | --- |
| A: [稳妥方法] | 模型成熟，实现的成功率高，评委认可度高。创新性不足但不会出错 | ⭐⭐⭐ |
| B: [平衡方法] | 在标准方法上做了有意义的改进，有加分潜力。需要额外 2-3 小时实现和调试 | ⭐⭐ |
| C: [激进方法] | 创新性强，如果成功了是亮点。风险：实现难度高，可能翻车导致时间不足 | ⭐ |
```

### 模板 3：创新取舍决策

```markdown
## 决策 3：创新冒险程度

**背景**：当前可以走稳妥路线（大概率省一/国二）或冒险路线（可能冲国一也可能翻车）。

**为什么需要你来选**：这取决于你的目标、时间预算和风险偏好。

### 选项

| 选项 | 分析 | 推荐度 |
| --- | --- | --- |
| A: 稳扎稳打 | 所有方法选成熟方案，重点放在结果分析和图表质量上。下限高，上限有限 | ⭐⭐⭐ |
| B: 局部创新 | 在 2 个子问题上做方法创新，其他子问题用稳妥方案。平衡风险和加分 | ⭐⭐ |
| C: 全面创新 | 每个子问题都用进阶方法，追求最大差异化。高风险高回报 | ⭐ |
```

### 模板 4：图表策略决策

```markdown
## 决策 4：图表取舍

**背景**：代码阶段生成了 15 张图表，但论文正文空间有限（建议 8-10 张）。

**为什么需要你来选**：哪些图进正文、哪些放附录、哪些舍弃，涉及对论文叙事线的判断。

### 选项（可多选）

| 选项 | 分析 | 推荐度 |
| --- | --- | --- |
| A: [图表A] | 展示 [什么信息]，是论证 [哪个结论] 的核心证据 | ⭐⭐⭐ |
| B: [图表B] | 辅助理解 [某个概念]，可视化效果好但不是必须 | ⭐⭐ |
| C: [图表C] | 信息量丰富但解读需要较多篇幅，适合放附录 | ⭐ |
```

### 模板 5：叙事重心决策（5writing 开始前）

```markdown
## 决策 5：论文叙事重心

**背景**：论文篇幅有限，需要有明确的叙事重心和强调方向。

**为什么需要你来选**：不同的评委偏好不同的亮点类型，且取决于你们的实际优势。

### 选项

| 选项 | 分析 | 推荐度 |
| --- | --- | --- |
| A: 方法创新为重 | 强调模型设计的新颖性，方法与文献的对比分析。适合方法确实有创新时 | ⭐⭐⭐ |
| B: 结果分析为重 | 强调数值结果的深度解读、业务含义和决策建议。适合结果有故事可讲时 | ⭐⭐ |
| C: 工程完整性为重 | 强调数据处理、模型验证、鲁棒性分析的全面性。适合数据量大、流程复杂时 | ⭐⭐ |
```

### 模板 6：摘要方向决策（abstract-polish 中）

```markdown
## 决策 6：摘要版本选择

**背景**：已生成 3 个不同策略的摘要版本（详见 ABSTRACT_VERSIONS.md）。

**为什么需要你来选**：不同版本在逻辑连贯性、创新呈现、简洁性之间权衡不同。

### 选项

| 选项 | 分析 | 推荐度 |
| --- | --- | --- |
| A: 逻辑强化版 | 子问题递进关系清晰，读起来像完整故事。可能稍微冗长 | ⭐⭐⭐ |
| B: 亮点突出版 | 创新点突出，冲击力强。可能需要牺牲一些技术细节 | ⭐⭐ |
| C: 混合优化版 | 从各版取最优段落混合。需要人工检查混合后的连贯性 | ⭐⭐ |
```

## 与其他 Skill 的协作

- `1start-mathmodel`：在 plan.md 中标注预期决策节点
- `2analysis-modeling`：产出歧义清单，触发「方向确认决策」
- `model-comparison`：产出方法池和对比矩阵，触发「模型选型决策」
- `3coding-visual`：产出图表清单，触发「图表策略决策」
- `deep-sensitivity`：产出灵敏度发现，触发「哪些发现进论文」决策
- `abstract-polish`：产出多版摘要，触发「摘要方向决策」
- `5writing`：开始前触发「叙事重心决策」
- `6verity`：验收时如果发现需要人工判断的问题，触发最终决策

## 质量要求

- 每个决策必须说明「为什么需要你来选」——如果 AI 可以合理自动决定，就不要问。
- 推荐度不能全相同——必须有 ⭐⭐⭐ 表明 AI 态度。
- 选项分析必须具体，不能说「各有利弊」这种废话。每种选择有具体的优势、风险、代价。
- 不要连续弹出过多决策（一次最多 4 个问题）。如果决策超过 4 个，分两轮。
- 用户的每个选择必须被记录并注入后续流程——不能问了等于白问。
