# 编程实现与数据图表生成

本 skill 承接 `2analysis-modeling`。目标是把 `reports/ANALYSIS_MODELING_REPORT.md` 里的模型和算法落实为可复现程序，跑出可信结果，并生成论文中需要的数据型图表。

## 求解器真实性要求（硬性标准，不可跳过）

**建模竞赛的代码不是脚本拼接，是真正的优化/仿真/学习。贪心算法、规则排序、公式套用不能替代求解。**

| 题目类型 | 必须使用的求解方式 | 如何证明你真的求解了 |
| --- | --- | --- |
| **优化类** | 必须调用优化求解器：PuLP/CBC, Gurobi, CPLEX, OR-Tools, SciPy.optimize, cvxpy 之一 | 日志中必须出现：Optimal/Feasible/Iteration/Node/Branch/Gap 等求解器输出 |
| **预测/分类类** | 必须使用 sklearn/statsmodels/pytorch 的 fit/predict 流程 | 日志中必须出现训练/验证划分、模型参数、评估指标 |
| **仿真/机理类** | 必须使用 scipy.integrate/模拟框架，至少跑够最低采样数 | 日志中必须出现步长/迭代/收敛信息 |
| **启发式算法** | 可作为初始解生成或对比方案，**不可作为唯一求解方法** | 必须与精确求解器结果对比，报告 gap |

**代码调试——禁止手改瞎试**：代码跑不通或结果异常时，**必须调用 `systematic-debugging` skill**。它会结构化分析错误类型→定位根因→针对性修复。不要自己反复改参数试——这是浪费时间且经常改错方向。2025 A题z方向bug就是手改试了6轮才发现。

**严禁的做法：**
- ❌ 只写贪心分配（按利润排序 + for 循环填地块）→ 这不是「求解」，这是「拍板」
- ❌ 把 1000 次「参数乘系数」当成 1000 次「蒙特卡洛求解」
- ❌ Sobol 敏感性分析的每次评估 = 公式代值（必须每次重新求解模型）
- ❌ 代码里没有调用任何求解器/优化库，但论文里写「使用 MILP 求解」
- ❌ 找临界值（碰撞时刻、最小螺距、最大速度等）用手工调几个参数 → **必须用二分法/黄金分割法/牛顿法精确搜索，报告收敛精度**
- ❌ 题面规定了方法（如「两段相切圆弧」），自己换成别的方法（如贝塞尔曲线）

**数值-理论双轨验证（机理/动力学类必做）**：

2022 A题教训：Q2(2) Pmax=2437W > 入射波功率680W，违反能量守恒。纯数值解无理论对照→翻车不自知。

| 验证方式 | 适用场景 | 说明 |
| --- | --- | --- |
| **能量守恒** | 所有动力学问题 | 阻尼耗能 ≤ 激励输入能量，违反=数值解错误 |
| **退化验证** | 极端参数 | 阻尼→∞时运动→0，阻尼→0时共振幅值→∞，检查是否符合物理直觉 |
| **量纲检查** | 所有方程 | 每一项的量纲必须一致 |
| **解析解对照** | 线性系统 | 简谐激励下的稳态解析解（拉普拉斯变换）与数值解对比 |

验证结果写入 RESULTS_REPORT.md，不通过 → CP2 FAIL。

**求解方法选择规范（打破网格搜索垄断）**：

**六道题只用网格搜索→方法论单调。以下为不同场景的方法选择优先级：**

| 场景 | 首选方法 | 备选 | 禁止 |
| --- | --- | --- | --- |
| 低维连续优化(≤4变量) | **自适应网格搜索** | PSO/GA | — |
| 中高维连续优化(5-20变量) | **PSO** (快速收敛) | GA/SA | 纯网格搜索(维度灾难) |
| 离散/混合变量 | **GA** (天然支持离散) | SA | PSO(需改造) |
| 多峰/非凸/带噪声 | **SA** (逃离局部) | PSO(多起点) | 梯度下降 |
| 组合优化/任务分配 | **GA** + 匈牙利算法 | — | 网格搜索 |
| 零点/阈值精确搜索 | **二分法** | 黄金分割 | 手工调参 |
| 低维粗定位+精搜 | **adaptive_grid_search** | PSO | GA(收敛慢于PSO) |

**代码中必须导入并使用**：`from solver_templates import GA, PSO, SA, bisection_search, adaptive_grid_search`（文件位于 `scripts/solver_templates.py`）。不要从零手写优化器。**首次使用前必须先 `import sys; sys.path.insert(0, 'references')` 确保路径可达。**

**临界值搜索强制规范**：
任何需要找到「首次发生XX的时刻」「最小可行XX」「最大允许XX」的问题，必须使用精确数值搜索方法：

| 搜索类型 | 必须使用的方法 | 输出要求 |
| --- | --- | --- |
| 零点/阈值搜索 | 二分法 | 报告迭代次数、最终区间宽度、收敛精度 |
| 参数优化 | 黄金分割法/二分法 | 报告搜索范围、收敛准则 |
| 多极值 | 网格搜索+局部二分 | 报告网格密度、各局部极值 |

**在 `reports/RESULTS_REPORT.md` 中必须包含求解器输出日志摘要。**

## 图片质量通用标准

### 零、图表不单调保障（所有题目通用——防全是折线图）

**每篇论文的图表必须覆盖以下三个维度，缺一不可：**

| 维度 | 要求 | 说明 |
| --- | --- | --- |
| **数据图** | ≥60%的图 | 折线/散点/柱状/热力图等，展示数据和结果 |
| **原理图** | ≥2张 | TikZ绘制的物理机制/算法流程/几何构造示意图。**即使题目没有给图，也要自己画。** |
| **细节图** | ≥2张 | 关键区域的局部放大、多方法对比、不同参数下的叠加对比。展示你「认真看过数据」。 |

**单调检测**：如果图表类型少于柱状图+折线图+散点图+热力图+原理图五种中的三种 → 图太单调，必须补充。

### 一、图表类型多样性（AI 根据题目特征判断）

**一张论文不能全是柱状图或全是折线图。你必须根据题目特征，覆盖 ≥5 种不同的图表类型。**

AI 在生成图表前，必须根据题目的以下特征自动判断需要哪些类型的图：

| 题目特征 | 需要的图表类型 | 不少于 |
| --- | --- | --- |

| 涉及空间分布 | 空间位置散点/轨迹图、密度分布、区域对比 | 2张 |
| 涉及优化/寻优 | 收敛曲线、可行域可视化、目标函数曲面/等高线 | 2张 |
| 涉及多方案对比 | 分组柱状图、雷达图、平行坐标图 | 2张 |

**3D立体图形要求**：

当题目涉及三维空间运动（导弹飞行、无人机航迹、烟幕弹轨迹、波浪装置等），必须使用 `mpl_toolkits.mplot3d` 生成至少 3 张 3D 立体图，包含：
- **3D轨迹总览图**：所有运动体(M1/UAV/烟幕)在三维空间中的完整轨迹，用不同颜色区分
- **局部放大图**：遮蔽发生时刻的局部三维空间关系，标注关键距离和几何关系
- **多视角投影**：至少给出 xy、xz、yz 三个平面的投影视图，便于分析各方向的几何关系

3D图代码模板：

fig = plt.figure(figsize=(12, 9))

## 计算深度最低要求（硬性标准，不可跳过）

**数模竞赛的竞争力来自计算深度。不是「跑一遍出个结果就行」，而是「跑够了才能说明结果可信」。以下为硬性最低标准：**

| 场景 | 最低计算量 | 为什么要这么多 |
| --- | --- | --- |
| **蒙特卡洛仿真** | ≥ 10,000 次采样 | 100 次和 10000 次的均值差异可达 5%+；置信区间宽度与 √N 成反比 |
| **启发式算法（GA/SA/PSO）** | ≥ 20 次独立运行，每次不同随机种子 | 单次运行可能是局部最优；报告均值±标准差是基本学术规范 |
| **交叉验证** | ≥ 5 折，时序数据用 TimeSeriesSplit | 3 折的方差太大，5 折是机器学习社区的最低共识 |
| **超参数调优** | 每个超参数 ≥ 3 个候选值，网格搜索或随机搜索 ≥ 20 组组合 | 单组超参数的结果不可信，实际可能是过拟合的最优假象 |
| **收敛判断** | 迭代算法必须设收敛阈值（如目标值变化 < 1e-6 或 迭代 > 500 次无改善），不能固定跑 100 次就停 | 不同问题收敛速度差异巨大 |
| **约束验证** | 最优解必须逐条回代所有约束，输出「约束名、值、边界、松弛量、是否活跃」五列 | `success=True` 不意味着解真的可行 |

**在 `reports/RESULTS_REPORT.md` 的「运行环境」小节中，必须列出以上各项的实际计算量和达标情况。未达标的必须说明原因和替代验证方案。**

**预计耗时**：根据问题复杂度，本阶段代码运行可能需要 30 分钟到数小时。这不是 bug，是计算深度。在 plan.md 中标注预计计算时间。

- 本阶段不写论文正文，只为 `5writing` 提供可信数值和图表资产。


### Step 1: 代码结构

按 `plan.md` 中"项目目录结构"创建 `code/` 和 `figures/` 骨架，再开始写代码。子问题数不一定是 3，按赛题实际数量调整。


### Step 2: 逐子问题实现

按子问题顺序实现，不要一次性写完不跑。

每个子问题必须完成：

1. 读取所需数据。
2. 实现模型或算法。
3. 验证约束。
4. 输出核心结果。
5. 绘制丰富的图表。
6. 在 `reports/RESULTS_REPORT.md` 中写清楚方法、关键数值和校验结果。

优化类问题必须先保证可行解，再优化目标值。预测类问题必须做训练/验证划分或合理误差评估。评价类问题必须说明指标方向、归一化方法和权重来源。

### Step 3: 结果文件格式


AI 在实现、求解和作图过程中，必须把关键中间过程保存成数据并做好记录，例如清洗后的数据摘要、模型参数、迭代历史、约束检查、灵敏度分析过程、图表所用数据和运行日志。中间数据优先保存到 `figures/` 或 `code/outputs/`，并在 `reports/RESULTS_REPORT.md` 中说明文件用途。

`reports/RESULTS_REPORT.md` 推荐结构：

```markdown
# 计算结果

## 运行环境
## 数据读取与预处理
## 问题一结果
## 问题二结果
## 问题三结果
## 灵敏度分析
## 约束与一致性校验
## 与建模报告的一致性说明
## 可复现运行方式
```

所有数据和图表结果都必须出现在 `reports/RESULTS_REPORT.md` 中引用

### Step 4: 生成数据驱动图表

根据 `reports/ANALYSIS_MODELING_REPORT.md` 和 `reports/RESULTS_REPORT.md` 规划图表，生成 PDF 到 `figures/`。

典型图表：

- 预测类：真实值-预测值对比、误差分布、指标对比。
- 优化类：收敛曲线、成本对比、资源利用率、方案前后对比。
- 评价类：综合得分排序、雷达图、热力图、敏感性曲线。
- 数据理解：分布图、趋势图、相关性图、箱线图。

图表要求：

- PDF 矢量输出，适合论文。
- 不在图内写大标题，标题交给论文 caption（Typst 的 `caption:` 或 LaTeX 的 `\caption{}`）。
- 中文论文图表使用中文坐标轴和图例；英文论文使用英文。
- 不生成流程图/架构图/路线图。

图表可以由主程序或独立脚本生成，不强制固定脚本名。无论采用哪种方式，都必须保存图表对应的数据来源和生成记录。
