# 摘要精品打磨

## 数学建模规范参考

读取 `references/math_modeling_norms.md`（相对 skill 根目录，下同） 中的「摘要写作要点」「美赛专项规范」和「论文写作规范补充」。

## 前置条件

论文主体必须已完成（`5writing` 阶段产出）。如果论文不存在，提示用户先完成论文撰写。

## 必须产出

- `reports/ABSTRACT_VERSIONS.md`：多版摘要对比、评分和最终推荐。
- 在论文文件中替换或插入打磨后的摘要。

---

## 工作流程

### Step 0: 判断比赛类型和摘要格式

```markdown
## 比赛类型识别

- 中国赛（CUMCM/省赛）：摘要独立页面，一般不超过两页，中文
- 美赛（MCM/ICM）：Summary Sheet 独立一页，英文，不计入 25 页
- 其他：按具体要求
```

据此确定摘要的语言、长度和格式要求。

### Step 1: 信息清单提取

从各阶段产物中提取摘要必须包含的硬信息：

```markdown
## 摘要信息清单

### 问题一
- 方法：...
- 模型名/核心公式：...
- 关键结果（数值）：...
- 结果含义：...

### 问题二
- ...

### 模型亮点
- 创新点 1：...
- 创新点 2：...

### 验证/灵敏度关键发现
- ...
```

**硬规则**：
- 数值必须从 `reports/RESULTS_REPORT.md` 直接复制，不重新估算
- 每个子问题必须覆盖：方法 + 模型 + 结果 + 含义
- 如有创新点（来自 `reports/MODEL_SELECTION_REPORT.md`），至少 1 个需要在摘要中体现

### Step 2: 第一版摘要生成

基于信息清单，生成第一版摘要。

**结构模板**：

```
[第 1 段] 问题背景和总体思路（1-2 句）
[第 2 段] 问题一：方法 + 模型 + 关键结果
[第 3 段] 问题二：方法 + 模型 + 关键结果（注意与问题一的递进关系）
[第 N 段] 问题 N：...
[倒数第 2 段] 模型检验与灵敏度分析关键发现
[最后 1 段] 模型特点与创新点总结
```

**写作要求**：
- 不使用「我们」「本文」开头的空泛句子
- 不出现复杂公式和表格
- 不重述题面（假设读者已知道题目）
- 每个数值要说清单位/含义
- 每个方法选择要有简短理由（为什么选这个方法）

### Step 3: 多维度评分

对第一版摘要按以下维度打分（每项 1-5 分）：

```markdown
## 摘要评分 — V1

| 维度 | 评分 | 问题 | 改进方向 |
| --- | --- | --- | --- |
| 完整性 | ?/5 | 是否每个子问题都有方法+模型+结果？ | ... |
| 数值准确性 | ?/5 | 数值是否与结果记录一致？单位是否标注？ | ... |
| 逻辑连贯性 | ?/5 | 子问题之间是否有递进关系表述？ | ... |
| 创新呈现 | ?/5 | 亮点是否清晰可辨？是否让人记住？ | ... |
| 简洁性 | ?/5 | 是否有冗余句子可以删除？ | ... |
| 冲击力 | ?/5 | 读完摘要评委是否想继续读正文？ | ... |
```

### Step 4: 多版本迭代

基于评分问题，生成 2-3 个差异化版本：

| 版本 | 策略 |
| --- | --- |
| V2 逻辑强化版 | 重点改进逻辑连贯性和子问题递进关系 |
| V3 亮点突出版 | 重点强化创新点呈现和冲击力 |
| V4 精简版 | 压缩到最短篇幅同时保持信息完整 |

每个版本独立评分，与 V1 对比：

```markdown
## 版本对比

| 维度 | V1 | V2 | V3 | V4 |
| --- | --- | --- | --- | --- |
| 完整性 | 4 | 4 | 4 | 3 |
| 数值准确性 | 5 | 5 | 5 | 5 |
| 逻辑连贯性 | 3 | 5 | 4 | 3 |
| 创新呈现 | 2 | 3 | 5 | 2 |
| 简洁性 | 3 | 3 | 3 | 5 |
| 冲击力 | 2 | 3 | 5 | 2 |
| **总分** | 19 | 23 | **26** | 20 |
```

### Step 5: 混合优化

取各版本最优句子/段落，混合为一版：

```markdown
## 最终推荐版本

[混合版摘要全文]

**混合来源**：
- 第 X 段来自 V3（原因是...）
- 第 Y 段来自 V2（原因是...）
```

### Step 6: 替换论文摘要

将最终推荐版本写入论文文件对应位置。

**注意**：
- Typst 模板：找到摘要区域（通常在 `#show: ...` 或专门的 abstract 章节）
- LaTeX 模板：找到 `\begin{abstract}...\end{abstract}` 或 `\makesheet` 命令
- 检查编译后摘要的页数（中国赛 ≤ 2 页，美赛 Summary Sheet = 1 页）

### Step 7: 一致性检验

```markdown
## 摘要-正文一致性检验

| 检查项 | 摘要中的值 | 正文对应位置的值 | 是否一致 |
| --- | --- | --- | --- |
| 问题一误差 | 3.2% | 第 X 节：3.2% | ✅ |
| 问题二最优值 | 1234.56 | 第 Y 节：1234.56 | ✅ |
| ... | ... | ... | ... |
```

任何不一致都需要修正。

## 摘要写作速查

### 常见问题（必须避免）

| 问题 | 坏例 | 好例 |
| --- | --- | --- |
| 空泛开头 | 「随着…的发展，…问题日益重要」 | 直接说模型做了什么 |
| 只列方法不给结果 | 「采用 AHP 进行评价」 | 「AHP 评价结果方案 3 得分最高（0.78）」 |
| 数值无单位 | 「误差为 3.2」 | 「预测误差 3.2%（MAPE）」 |
| 子问题间无递进 | 「问题一…。问题二…。」 | 「在问题一的最优方案基础上，问题二进一步优化了…」 |
| 亮点淹没 | 埋在段落中间 | 在最后一段集中呈现，用「本文创新之处在于…」引出 |
| 过度谦虚/过度自信 | 「还比较准确」「极其完美」 | 「误差控制在 5% 以内」「达到预期精度要求」 |

### 美赛 Summary Sheet 特别要求

- 必须是独立一页
- 必须包含：Problem Chosen, Summary, 团队编号（如有）
- 总结部分：方法亮点 + 关键结论 + 模型贡献
- 不要复制粘贴 Summary 和 Abstract 互相替代——它们是不同东西
- 英文须流畅自然，避免机器翻译痕迹（多用短句，少用复杂从句）

---

## 质量要求

- 摘要中的每个数值都必须能追溯到结果文件。
- 每个子问题在摘要中必须覆盖，不能遗漏任何问题。
- 摘要必须最后打磨——如果后续修改正文导致数值变化，必须同步更新摘要。
- 多版本对比不是为了凑数量——每个版本必须有明确的差异化策略。
- 最终推荐的摘要必须经过「替换→编译→再检查」的闭环验证。
